# 定时停止与当前段落定位（alpha.9）

更多菜单中的“定时停止”提供15、30、60分钟，以及1–720分钟自定义值。倒计时从点击设置开始；原生服务持有单调时钟截止时间，WebView只显示剩余时间。修改定时会替换原截止时间，取消定时不停止正在播放的内容。

- 暂停仍计时，恢复前检查是否到期。
- 手动停止、读完整个队列会取消定时；替换朗读队列继承尚未到期的截止时间。
- 到期取消本地合成/播放、待播队列以及前台云语音确认/播放，释放音频焦点、唤醒锁和通知。内置模型必须等待被取消的JNI调用退出后安全释放，不会在JNI运行中强行free。
- 到期后不会自行恢复。再次明确点击播放可开始新会话。
- 进程重启不恢复定时或朗读；Activity重建保留仍在运行的服务状态。
- 没有新增精确闹钟权限或额外常驻唤醒锁。活跃播放使用既有媒体服务及有界唤醒锁。暂停后设备深度休眠可能让Handler清理延迟至唤醒，但原生会先核截止时间，阻止过期后继续播放。系统强制停止或厂商后台策略不是定时准确性保证。

更多菜单中的“定位当前朗读段落”定位最近确认开始播放的正文段落，可加载未呈现的正文组并高亮。它不重启音频，不把提前合成的下一段当正在朗读。暂停时仍可定位；停止、定时到期、错误或更换文档清除定位。默认不会随着朗读强行滚动，精度为段落级。

## 验证边界

原生JVM、JavaScript和设备回归必须按对应构建报告核验。设备定时测试使用固定合成内容和测试语音服务，以真实elapsedRealtime等待至少60秒，区分前台暂停、退到桌面、锁屏和云端待确认状态。不会调用付费语音或上传正文。真实Kokoro播放及释放沿用并保留alpha.8的设备回归。

开发依据：Android官方[SystemClock](https://developer.android.com/reference/android/os/SystemClock)与[Handler](https://developer.android.com/reference/android/os/Handler)文档；elapsedRealtime包含休眠，Handler按uptime安排执行，不能把网页计时或Handler回调时间当作绝对精确闹钟。
